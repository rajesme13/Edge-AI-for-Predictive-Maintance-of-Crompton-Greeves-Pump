# Industrial Edge-AI Framework for Predictive Maintenance of Electric Motors Using Multi-Sensor Fusion

A Python-based proof of concept for predictive maintenance of a Crompton Greaves CG-IPM-15 centrifugal pump motor. The project generates synthetic multisensor data for developing and testing a fault-classification and severity-estimation workflow.

> **Research and safety notice:** The data generated by this repository is synthetic, not measured from a physical motor. Baseline values are illustrative assumptions and are not verified CG-IPM-15 nameplate specifications. Do not use model outputs as the sole basis for industrial safety or maintenance decisions.

## Project objectives

- Represent motor operating conditions using voltage, current, temperature, and vibration features.
- Generate labeled synthetic data for software development and initial ML experiments.
- Explore fault-classification and severity-estimation workflows.
- Provide a starting point for later ESP32 sensor integration and edge inference.
- Document limitations that must be resolved through measured-data validation.

## System concept

1. **Acquire sensor values:** phase voltage, phase current, surface temperature, bearing-housing temperature, and vibration.
2. **Validate and preprocess:** check ranges, missing values, units, and sensor quality.
3. **Engineer features:** calculate statistical features and, for measured vibration waveforms, frequency-domain features.
4. **Classify operating condition:** predict a class from the supported labels.
5. **Estimate severity:** treat severity prediction as a separate task and evaluate it independently.
6. **Deploy at the edge:** after validation, optimize a suitable model for the selected embedded hardware.
7. **Monitor:** display condition estimates and alarms with appropriate fail-safe handling.

### Proposed hardware

| Component | Role |
|---|---|
| ESP32 | Sensor acquisition and potential edge inference |
| Isolated, appropriately rated voltage transducers | Three-phase voltage measurement |
| Current transformers or suitable Hall-effect transducers | Phase-current measurement |
| DS18B20 or industrial temperature sensors | Temperature measurement |
| ADXL345 or industrial accelerometer | Vibration sensing |
| Optional pressure and flow sensors | Additional evidence for pump cavitation and dry-run conditions |

**Electrical safety:** Never connect mains voltage directly to the ESP32 or its ADC pins. Use appropriately rated isolated sensing circuits and qualified supervision.

## Synthetic fault classes

The generator defines nine classes (normal operation plus eight simulated fault categories):

| Code | Class | Simulated condition |
|---:|---|---|
| 0 | `Normal` | Normal operating condition |
| 1 | `Bearing_Wear` | Bearing wear |
| 2 | `Shaft_Misalignment` | Shaft misalignment |
| 3 | `Rotor_Impeller_Imbalance` | Rotor or impeller imbalance |
| 4 | `Cavitation` | Pump cavitation |
| 5 | `Dry_Run_Low_Suction` | Dry-run or low-suction condition |
| 6 | `Overload` | Motor overload |
| 7 | `Phase_Voltage_Imbalance` | Three-phase voltage imbalance |
| 8 | `Winding_Overheating` | Winding overheating |

These are simulated labels and do not prove that these faults can be distinguished reliably from real sensor data.

## Severity labels

| Level | Label | Meaning in the generator |
|---:|---|---|
| 0 | Normal | Normal class; no simulated fault |
| 1 | Mild | Mild simulated fault condition |
| 2 | Moderate | Moderate simulated fault condition |
| 3 | Severe | Severe simulated fault condition |

Severity labels are synthetic categories, not certified thresholds or validated risk levels. Practical limits must be established using manufacturer information, engineering standards, calibrated measurements, and controlled validation.

## Sensor parameters and units

| Parameter | Unit |
|---|---|
| Phase 1, 2, and 3 voltage; mean voltage | V |
| Voltage unbalance | % |
| Phase 1, 2, and 3 current; mean current | A |
| Current unbalance | % |
| Stator surface temperature | °C |
| Bearing housing temperature | °C |
| Ambient temperature | °C |
| Simulated load fraction | Dimensionless ratio (0–1) |
| Vibration X/Y/Z RMS and vector RMS | g in the current CSV |
| Sample ID and fault code | Unitless identifiers |

For acceleration in SI units, convert g to m/s² using **1 g = 9.80665 m/s²**. Celsius is used for practical temperature reporting; the SI unit of thermodynamic temperature is kelvin (K).

## Run the generator

Clone the repository:

```bash
git clone https://github.com/rajesme13/Edge-AI-for-Predictive-Maintance-of-Crompton-Greeves-Pump.git
cd Edge-AI-for-Predictive-Maintance-of-Crompton-Greeves-Pump
```

Generate the dataset:

```bash
python code_synthetic_data.py
```

The script prints the record count, number of classes, and class counts. Its default setting is `SAMPLES_PER_FAULT = 1000`. In the current code, each non-normal fault's samples are divided across three severity levels; integer division means the total can be slightly below the nominal setting. The normal class uses severity level 0 only.

The script writes:
- `cg_ipm15_synthetic_dataset.csv`
- `fault_label_dictionary.csv`

into the current working directory. The script overwrites these output files if they already exist, so keep backups of any data you need.

## Suggested machine-learning workflow

1. Inspect feature ranges, missing values, duplicates, and class/severity counts.
2. Separate features from target labels such as `fault_type` or `severity_level`.
3. Establish simple baselines, for example Decision Tree, Random Forest, or Gradient Boosting.
4. Evaluate with a confusion matrix, per-class precision and recall, macro F1-score, and balanced accuracy where appropriate.
5. Keep fault classification and severity estimation as distinct tasks unless a justified multi-task design is implemented.
6. Test on independently generated operating scenarios, not only a random split of samples created by the same rules.
7. Once physical data is available, hold out separate sessions or runs for more realistic evaluation.
8. Measure inference latency, RAM/flash use, and robustness before considering embedded deployment.

**Avoid data leakage:** Random train/test splitting can produce overly optimistic results when records share the same generation rules. High scores on this synthetic dataset do not establish real-world fault-diagnosis performance.

## Limitations

- All generated measurements are synthetic, and the assumed baseline values are illustrative.
- Fault effects are simplified and overlapping; they are not universal physical diagnostic laws.
- Voltage, current, temperature, and vibration RMS alone may not uniquely identify all fault types.
- Cavitation and dry-run diagnosis can benefit from pressure, suction, and flow measurements.
- Reliable bearing or mechanical diagnosis may require waveform-level vibration sampling, appropriate mounting, and spectral features such as FFT-derived indicators.
- Winding temperature is not directly measured by a surface-temperature proxy.
- The project does not establish remaining useful life or time-to-failure unless a separate, validated prognostics method is developed.
- ESP32 deployment and real-time performance have to be tested on the actual hardware.
- Actual CG-IPM-15 nameplate parameters must be verified independently before using the framework on the physical motor.

Report current results as **synthetic-data proof-of-concept results** until independent measured-data validation has been completed.
